Today's Miss Patterns Drill

Pattern 1 — Read + Write fallback (appeared twice). When Edit fails on non-unique anchor text → don't Grep + replace-all. Use Read to load the full file, modify the intended block, then Write the complete corrected file. Grep + replace-all changes unintended occurrences.
Pattern 2 — Stratified sampling. Uniform sampling misses rare segments even at higher rates. When failures are concentrated in a low-volume slice → stratify by segment (issue type, channel, age, action). Confidence thresholds don't fix coverage gaps.
Pattern 3 — -p / --print for CI. --print = non-interactive mode (exits after output). --output-format json = structured parsing. Different problems. CI hangs = interactivity problem = use --print.

D4 Quick Reference — Prompt Engineering

When to use criteria vs. examples Key distinction
SituationFix
Definition is missing — model has no basis to judgeCriteria first — write explicit rules
Criteria are clear but output is inconsistentAdd few-shot examples — anchor the pattern
Prose instructions keep failing despite editsSkip to examples — don't add more instructions
Edge case behavior needs to be locked inContrastive examples — show right vs. wrong
Rule: More instructions ≠ better behavior. When prose fails, examples are the fix — not more prose.
Enums with unknown fields Key distinction

When a field has a fixed set of values but real inputs won't always match — add an "other" escape value plus a companion detail field. Never make the schema hallucinate a false category.

Anti-pattern
enum: ["return", "billing", "account"]

Forces model to pick a category even when none fits → hallucination pressure on every misfit input.
Correct pattern
enum: ["return", "billing", "account", "other"]
+ companion field: "issue_detail": string | null

Model picks "other" and puts the real value in issue_detail. No forced hallucination.
Rule: Required fields with no reliable source = hallucination pressure. Nullable companion fields are the safety valve.
tool_choice: auto vs any vs forced Core
ValueBehaviorWhen to use
{"type": "auto"}Model decides whether to use a toolDefault — open-ended tasks
{"type": "any"}Must use some tool, model picks whichForce structured output without fixing which tool
{"type": "tool", "name": "..."}Must use this specific toolFirst turn extraction, then switch back to auto
Pattern: Force tool on turn 1 for structured extraction → switch to auto for follow-up turns.
Batch API Core
  • Use when: latency-tolerant, nightly jobs, bulk classification, cost-sensitive at scale
  • Correlate results via custom_id — not position
  • On partial failure: resubmit only failed custom_ids, not the full batch
  • Not for: real-time, interactive, or conversational flows
Trap: "nightly classification job" → Batch API. "User-facing chat" → never Batch.

D1 — Agentic Architecture (27% — Strongest Domain)

Agentic loop skeleton Mastered
  1. Call API → check stop_reason
  2. If tool_use → execute all tool calls (parallel if independent)
  3. Append tool_result blocks for every tool call in that response
  4. Recurse → repeat until stop_reason == "end_turn"
  5. Handle max_tokens → resume with continuation prompt
Coordinator pattern Key

Coordinator = centralized visibility + error handling + information control. It holds state, dispatches to subagents, and decides what context each subagent gets. Subagents should not share state directly.

PostToolUse hook beats wrapper tools for output normalization — it's centralized, covers third-party tools, and doesn't require per-tool implementation.
Constrained tools > generic tools Key
Generic (anti-pattern)
fetch_url — unrestricted, can fetch anything
Constrained (correct)
load_document(id) — scoped to known sources, auditable

When a tool is misused → fix: replace with a constrained alternative. Don't route around it.

D2 — MCP Tool Design (18% — Weakest Domain)

Tool description is the first fix Watch
  • Model misroutes to the wrong tool → fix the description, not the routing layer
  • Overlap between tools → split them or add disambiguation language
  • MCP resources = on-demand context, not a forced round-trip (≠ tool_choice forced)
  • Composite tools vs. prompt-level batching — composite when the operations always go together; batching when they're independent
